# KAVACH — Data Model & Storage Architecture

## 1. Overview

Kavach employs a dual-storage architecture combining a structured relational database (**SQLite / SQLAlchemy ORM**) for transactional integrity and auditability, alongside a vector database (**ChromaDB**) for semantic intelligence matching and statutory legal retrieval.

```
+-----------------------------------------------------------------------------------+
|                                KAVACH DATA LAYER                                  |
|                                                                                   |
|  +------------------------------------------------+  +-------------------------+  |
|  |             RELATIONAL SQLITE DATABASE         |  |   CHROMADB VECTOR DB    |  |
|  |                                                |  |                         |  |
|  |  - Auth & Citizens: users, gps_pings, consent  |  |  - kavach_offender_     |  |
|  |  - Incidents & Cases: incidents, cases         |  |    profiles (Embeddings)|  |
|  |  - Intelligence: offenders, candidates, verify |  |                         |  |
|  |  - Geospatial: risk_zones, heatmap_cells       |  |  - kavach_legal_        |  |
|  |  - Support & Redress: chat_sessions, messages  |  |    documents (BNS RAG)  |  |
|  |  - Telemetry: evidence_events, audit_events    |  |                         |  |
|  +------------------------------------------------+  +-------------------------+  |
+-----------------------------------------------------------------------------------+
```

## 2. Relational Schema Reference (SQLite / SQLAlchemy)

### 2.1. Authentication & User Management

#### `users`
Represents registered platform citizens and law enforcement officers.
- `id` (INTEGER, Primary Key, Autoincrement)
- `username` (VARCHAR(100), Unique, Indexed, Not Null)
- `email` (VARCHAR(255), Unique, Indexed, Not Null)
- `hashed_password` (VARCHAR(255), Not Null) — bcrypt hash
- `role` (VARCHAR(50), Not Null, Default: `ROLE_USER`) — Scopes: `ROLE_USER`, `ROLE_AUTHORITY`
- `is_active` (BOOLEAN, Default: `True`)
- `created_at` (DATETIME, UTC timestamp)

#### `consent_events`
Stores audit logs for citizen tracking mode switches and privacy disclosures.
- `id` (INTEGER, Primary Key, Autoincrement)
- `user_id` (INTEGER, Foreign Key -> `users.id`, Nullable)
- `event_type` (VARCHAR(100), Not Null) — e.g., `MODE_CHANGE_REQUEST`, `MODE_CHANGE_ACCEPTED`
- `prompt_context` (TEXT, Not Null) — Explanatory prompt provided to citizen
- `user_decision` (VARCHAR(50), Not Null) — `ACCEPTED`, `REJECTED`, `DISMISSED`
- `timestamp` (DATETIME, UTC timestamp)

#### `gps_pings`
Time-series coordinate telemetry logged during active citizen navigation.
- `id` (INTEGER, Primary Key, Autoincrement)
- `user_id` (INTEGER, Foreign Key -> `users.id`, Nullable)
- `session_id` (VARCHAR(100), Indexed, Not Null)
- `latitude` (FLOAT, Not Null)
- `longitude` (FLOAT, Not Null)
- `speed` (FLOAT, Default: 0.0)
- `timestamp` (DATETIME, UTC timestamp)
- `current_mode` (VARCHAR(50), Default: `MANUAL`) — `MANUAL` or `LIVE`
- `zone_risk_level` (VARCHAR(50), Default: `LOW`) — `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`

---

### 2.2. Incidents & Case Management

#### `incidents`
Raw citizen-reported safety incidents before or after sanitization.
- `id` (INTEGER, Primary Key, Autoincrement)
- `incident_id` (VARCHAR(100), Unique, Indexed, Not Null) — e.g., `INC-2026-BBSR-001`
- `user_id` (INTEGER, Foreign Key -> `users.id`, Nullable)
- `timestamp` (DATETIME, UTC timestamp)
- `latitude` (FLOAT, Not Null)
- `longitude` (FLOAT, Not Null)
- `address` (VARCHAR(255), Not Null)
- `category` (VARCHAR(100), Not Null) — e.g., `Stalking`, `Harassment`, `Suspicious Loitering`
- `severity` (VARCHAR(50), Not Null) — `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`
- `description` (TEXT, Not Null) — Raw description submitted by citizen
- `pii_redacted_description` (TEXT, Not Null) — Regex and HMAC-scrubbed text
- `status` (VARCHAR(50), Default: `OPEN`)
- `created_at` (DATETIME, UTC timestamp)

#### `cases`
Consolidated investigation files aggregating incidents, legal drafts, and evidence.
- `id` (INTEGER, Primary Key, Autoincrement)
- `case_id` (VARCHAR(100), Unique, Indexed, Not Null) — e.g., `KAVACH-CASE-2026-0812`
- `victim_token` (VARCHAR(255), Indexed, Not Null) — HMAC-SHA256 deterministic token (`TOK_USR_...`)
- `incident_ids_json` (TEXT, Default: `[]`) — JSON array of associated incident IDs
- `title` (VARCHAR(255), Not Null)
- `category` (VARCHAR(100), Not Null)
- `status` (VARCHAR(50), Default: `ACTIVE`) — `ACTIVE`, `UNDER_INVESTIGATION`, `RESOLVED`
- `priority` (VARCHAR(50), Default: `NORMAL`) — `LOW`, `NORMAL`, `HIGH`, `URGENT`
- `legal_draft` (TEXT, Nullable) — Formal BNS-grounded complaint generated by Legal Agent
- `compiled_dossier_json` (TEXT, Nullable) — Serialized chronological evidence dossier
- `created_at` (DATETIME, UTC timestamp)
- `updated_at` (DATETIME, UTC timestamp)

---

### 2.3. Offender Intelligence & Multi-Source Verification

#### `offenders`
Fictional known perpetrator profiles for vector matching demonstrations.
- `id` (INTEGER, Primary Key, Autoincrement)
- `offender_code` (VARCHAR(100), Unique, Indexed, Not Null) — e.g., `OFF-BBSR-701`
- `alias` (VARCHAR(100), Not Null)
- `physical_description` (TEXT, Not Null) — Stature, facial marks, scars, tattoos, attire patterns
- `modus_operandi` (TEXT, Not Null) — Target profile, timing, vehicle usage, confrontation style
- `crime_history_json` (TEXT, Default: `[]`) — JSON array of past recorded offenses
- `known_areas_json` (TEXT, Default: `[]`) — JSON array of geographic operational sectors
- `active_status` (BOOLEAN, Default: `True`)
- `created_at` (DATETIME, UTC timestamp)

#### `incident_offender_candidates`
Association table linking candidate suspects to cases with similarity scores.
- `id` (INTEGER, Primary Key, Autoincrement)
- `case_id` (VARCHAR(100), Foreign Key -> `cases.case_id`, Indexed, Not Null)
- `offender_id` (INTEGER, Foreign Key -> `offenders.id`, Not Null)
- `match_score` (FLOAT, Not Null) — Combined hybrid similarity metric (0.00 – 1.00)
- `verification_status` (VARCHAR(50), Default: `PENDING`) — `VERIFIED`, `UNVERIFIED`, `REJECTED`
- `notes` (TEXT, Nullable)
- `created_at` (DATETIME, UTC timestamp)

#### `verification_results`
Deterministic audit log proving whether a suspect match meets statutory verification criteria.
- `id` (INTEGER, Primary Key, Autoincrement)
- `candidate_id` (INTEGER, Foreign Key -> `incident_offender_candidates.id`, Not Null)
- `verification_path` (VARCHAR(50), Not Null) — `PATH_A_REGISTRY` or `PATH_B_CORROBORATION`
- `verified` (BOOLEAN, Not Null)
- `score` (FLOAT, Not Null)
- `rationale` (TEXT, Not Null)
- `corroboration_count` (INTEGER, Default: 0) — Number of independent reports ($N$)
- `threshold_met` (BOOLEAN, Not Null) — True if $N \ge 3$ or active registry record matched
- `verified_at` (DATETIME, UTC timestamp)

### 2.4. Geospatial Intelligence & Dynamic Heatmap

#### `risk_zones`
Static and dynamic threat polygons/circles across Bhubaneswar.
- `id` (INTEGER, Primary Key, Autoincrement)
- `zone_name` (VARCHAR(100), Unique, Indexed, Not Null) — e.g., `Infocity Sector 3 Outer Ring`
- `center_latitude` (FLOAT, Not Null)
- `center_longitude` (FLOAT, Not Null)
- `radius_meters` (FLOAT, Not Null)
- `base_risk_score` (FLOAT, Not Null) — Baseline danger level (0–100)
- `lighting_level` (VARCHAR(50), Not Null) — `POOR`, `MODERATE`, `GOOD`
- `historical_incident_count` (INTEGER, Default: 0)
- `patrol_frequency` (VARCHAR(50), Not Null) — `FREQUENT`, `OCCASIONAL`, `NONE`
- `description` (TEXT, Nullable)
- `active` (BOOLEAN, Default: `True`)

#### `heatmap_cells`
Precalculated or dynamically computed spatial grid cells covering Bhubaneswar.
- `id` (INTEGER, Primary Key, Autoincrement)
- `cell_id` (VARCHAR(100), Unique, Indexed, Not Null)
- `latitude` (FLOAT, Not Null)
- `longitude` (FLOAT, Not Null)
- `risk_score` (FLOAT, Not Null) — Final computed risk metric (0–100)
- `incident_density` (FLOAT, Not Null)
- `recency_factor` (FLOAT, Not Null)
- `lighting_score` (FLOAT, Not Null)
- `computed_at` (DATETIME, UTC timestamp)

---

### 2.5. Support Dialogue & Evidence Dossier

#### `chat_sessions`
Citizen trauma-informed conversation sessions.
- `id` (INTEGER, Primary Key, Autoincrement)
- `session_id` (VARCHAR(100), Unique, Indexed, Not Null)
- `user_id` (INTEGER, Foreign Key -> `users.id`, Nullable)
- `created_at` (DATETIME, UTC timestamp)
- `active` (BOOLEAN, Default: `True`)

#### `chat_messages`
Individual dialogue messages with real-time distress detection markers.
- `id` (INTEGER, Primary Key, Autoincrement)
- `session_id` (VARCHAR(100), Foreign Key -> `chat_sessions.session_id`, Indexed, Not Null)
- `role` (VARCHAR(50), Not Null) — `user` or `assistant`
- `content` (TEXT, Not Null)
- `distress_detected` (BOOLEAN, Default: `False`)
- `handoff_triggered` (BOOLEAN, Default: `False`)
- `timestamp` (DATETIME, UTC timestamp)

#### `evidence_events` & `audit_events`
Immutable provenance trail logging all AI reasoning steps, tool executions, and case updates.
- `id` (INTEGER, Primary Key, Autoincrement)
- `case_id` / `agent_name` (VARCHAR(100), Not Null)
- `action` / `event_type` (VARCHAR(100), Not Null)
- `description` / `payload_summary` (TEXT, Not Null)
- `pii_free_log` / `metadata_json` (TEXT, Not Null) — Guaranteed free of raw victim identifiers
- `timestamp` / `logged_at` (DATETIME, UTC timestamp)

## 3. ChromaDB Vector Collections

Kavach isolates embeddings into two distinct ChromaDB vector collections under `data/chroma/`:

### 3.1. Collection: `kavach_offender_profiles`
- **Embedding Model**: Default sentence embeddings (or Gemini text embeddings).
- **Document Text**: Synthesized Modus Operandi + physical marks + vehicle + crime descriptions.
- **Metadata**:
  - `offender_code`: e.g. `OFF-BBSR-701`
  - `alias`: e.g. `Shadow Rider`
  - `known_areas`: Comma-separated list of sectors
  - `active_status`: `"true"`

### 3.2. Collection: `kavach_legal_documents`
- **Document Text**: Chunks of Bharatiya Nyaya Sanhita (BNS), BNSS, Protection of Women from Domestic Violence Act, Information Technology Act, and relevant IPC transitional tables.
- **Metadata**:
  - `doc_code`: e.g. `BNS-SEC-78`
  - `act_name`: e.g. `Bharatiya Nyaya Sanhita, 2023`
  - `section`: e.g. `Section 78 (Stalking)`
  - `category`: e.g. `Harassment & Stalking`
  - `chunk_index`: Integer index of chunk

## 4. Privacy Invariant & Serialization Contract

Whenever data moves across the boundary to the Authority Dashboard (`/api/authority/*`), the `PrivacyGuardianService` enforces:
1. **Never Serializing Raw Identifiers**: `victim_name`, raw phone number, and raw email are replaced with deterministic tokens (`TOK_USR_<HMAC>`) or `[REDACTED]`.
2. **Pydantic Model Enforcement**: The authority router returns `SanitizedAuthorityCaseResponse`, guaranteeing schema-level exclusion of sensitive victim fields.
